# ADR-018. Контракты StreamingPlanner и MeshJobScheduler

- **Статус:** Proposed — контракт согласован как направление; extraction и реализация ещё не выполнены.
- **Дата:** 11 ноября 2026 г.
- **Контекст:** Этап 1 ROADMAP. Текущие planner/scheduler обязанности находятся в наследуемых слоях `VoxelWorld`; `_wanted`, `_queued`, `_running_tasks`, `_running_by_coord` и `_completed_jobs` разделяют вычисление потребностей мира, планирование работ и жизненный цикл асинхронных задач.

## Проблема

Механический перенос методов из `VoxelWorld` в `RefCounted`-сервисы небезопасен. Планирование зависит от геометрии мира, поверхности, LOD-границ, движения игрока, hysteresis и topology fallback. Планировщик задач дополнительно зависит от seed, `generation_epoch`, соседних LOD, collision/shadow flags, cache key и семантики устаревших результатов.

## Решение / направление

Выделять сервисы поэтапно, без изменения алгоритмов генерации, LOD, приоритетов и streaming policy.

### StreamingPlanner

Чистый вычислительный сервис. Получает явный снимок входных данных:
- размеры мира и чанка, voxel scale и world origin;
- render distance, LOD boundaries и hysteresis;
- позицию/высоту игрока, heading и planar velocity;
- доступ к запросу высоты поверхности через узкий read-only интерфейс или заранее заданный sampler.

Возвращает план требуемых чанков и изменения topology. Не имеет ссылок на SceneTree/Node, не создаёт задачи, не меняет чанки, cache и runtime state. На первом этапе сохраняется существующая схема request Dictionary и packed `Vector2i` LOD key, чтобы не смешивать extraction с миграцией формата.

### MeshJobScheduler

Отдельный владелец очереди и жизненного цикла mesh jobs. Получает уже сформированные requests и immutable job envelope с координатой, request snapshot, соседними LOD, seed, `generation_epoch`, параметрами terrain snapshot и collision/shadow flags. Возвращает завершённые результаты владельцу мира; не добавляет/удаляет Node и не применяет MeshInstance/Physics resources.

Scheduler обязан:
- не запускать повторную задачу для той же координаты и совместимого request;
- сохранять ограничение общего worker budget с terrain/decor;
- переносить seed и epoch через весь job lifecycle;
- отбрасывать устаревшие результаты при смене epoch/seed/request;
- сохранять текущую семантику cache hit, retry и stale-result accounting.

### Граница ответственности VoxelWorld

До появления `GenerationContext` VoxelWorld остаётся авторитетным владельцем seed, `generation_epoch`, генератора и lifecycle мира. Он принимает результаты, проверяет их актуальность и применяет mesh/collision к сцене. Ни один новый сервис не должен самостоятельно увеличивать epoch или менять seed.

## Последовательность внедрения

1. Зафиксировать request/job record contracts и characterization tests на текущих функциях.
2. Выделить `StreamingPlanner` и сравнивать его выход с текущим алгоритмом на одинаковых deterministic inputs.
3. Выделить `MeshJobScheduler`; сохранить epoch/seed validation и shared worker budget.
4. Только после успешных регрессий перемещать ownership state и вводить `GenerationContext`.

## Критерии приёмки

- Одинаковые входы дают одинаковые wanted requests, LOD split/fallback topology и priority values.
- Проверены края мира и неполные граничные tiles.
- Проверены hysteresis при переходе через LOD boundary и fallback child readiness.
- Смена seed/epoch не позволяет применить старый результат.
- Cache hit и обычный worker completion дают эквивалентный валидный apply path.
- Сохранены collision/shadow flags, neighbor LOD inputs и cache-key semantics.
- Core CI и focused tests проходят; benchmark не показывает необъяснимой регрессии.

## Не входит в решение

Не менять генератор, TerrainField, mountain profile, LOD policy, cache format, mesh builder API, chunk scene ownership или общий worker budget в рамках одного extraction PR. Не начинать SDF/volume-grid работу на основании этого ADR.
